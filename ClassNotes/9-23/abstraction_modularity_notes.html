Abstraction & Modularity in C

A study guide for understanding how larger C programs are divided into reusable modules, how header and source files work together, and how abstraction and information hiding make programs easier to understand and maintain.

1. Abstraction

Abstraction means representing only the details that are important to the user of something while hiding details that are not currently necessary.

Main idea: abstraction separates what something does from how it does it.

Data Abstraction

Data abstraction lets a programmer work with a meaningful data type without constantly thinking about how every individual piece of data is stored. 

typedef struct {
    int day;
    int month;
    int year;
} Date;

A programmer can think of this as a Date instead of thinking separately about three integers every time it is used.

Operation Abstraction

Operation abstraction lets a programmer call a function based on what the function promises to do without needing to know the statements inside the function. 

int x = getx();
setx(10);

The caller only needs to know that getx() retrieves a value and setx() changes it.

Why Abstraction Matters

Real programs can contain thousands or millions of lines of code. No programmer can keep every implementation detail in mind at once. Abstraction allows the programmer to focus only on the part of the system that matters for the current task.

2. Modularity

Modularity is the practice of dividing a large program into smaller, logically related pieces called modules.

A module usually has two conceptual parts:

  • Interface: what the module makes available to other code.
  • Implementation: how the module actually performs its work.

The C standard library is built from modules. For example, functions from the mathematics library are declared through <math.h>.

Advantages of Modularity

  • Separates the what from the how.
  • Makes code easier to understand.
  • Allows useful code to be reused in other programs.
  • Makes testing easier because modules can be tested separately.
  • Makes maintenance easier because changes can often be limited to one module.
  • Allows multiple programmers to work on different modules at the same time.
Memory shortcut:
Abstraction hides unnecessary details.
Modularity organizes related functionality into separate pieces.

3. Using a Custom C Module

A simple C module is commonly split into:

File Typical extension Purpose
Specification / header file .h Declares the public interface.
Implementation / source file .c Contains the actual function definitions and private data.
Application source file .c Uses the module through its header.

Step 1: Create the Interface — fake_module.h

#ifndef FAKE_MODULE_H
#define FAKE_MODULE_H

int getx(void);
void setx(int value);

#endif

The header tells other source files which operations the module provides. It does not expose the private variable used to store the value.

Step 2: Create the Implementation — fake_module.c

#include "fake_module.h"

static int x = 0;

int getx(void) {
    return x;
}

void setx(int value) {
    x = value;
}
Important correction: if the header says void setx(int value);, then the implementation must also use void setx(int value). A definition such as void setx(int *value) would be a different function type and would conflict with the declaration.

Step 3: Use the Module — main.c

#include <stdio.h>
#include "fake_module.h"

int main(void) {
    setx(42);
    printf("x = %d\n", getx());
    return 0;
}

Step 4: Compile It

gcc main.c fake_module.c -o main
./main

Output:

x = 42
main.c | | #include "fake_module.h" v fake_module.h ---- tells main what functions exist ^ | | also included by | fake_module.c ---- contains the actual function definitions main.c + fake_module.c ---> compiler/linker ---> executable

4. Specification Files vs. Implementation Files

Specification File / Header File

The header acts as the module's public interface.

It commonly contains:

  • Function prototypes.
  • typedef declarations that users of the module need.
  • Constants or macros that are intentionally public.
  • Structure declarations when the structure must be visible to users.
  • Include guards.
int getx(void);
void setx(int value);

Implementation File

The implementation file contains the code that performs the module's work.

It commonly contains:

  • The corresponding header file.
  • Function definitions.
  • Private helper functions.
  • Private variables.
#include "fake_module.h"

static int x = 0;
Header file = what is available.
Source file = how it works.

5. #ifndef, #define, and #endif

These preprocessor directives are commonly used to make an include guard. The guard prevents the body of a header from being processed more than once in the same translation unit. 

#ifndef FAKE_MODULE_H
#define FAKE_MODULE_H

int getx(void);
void setx(int value);

#endif

What Each Line Means

Directive Meaning
#ifndef FAKE_MODULE_H If the symbol FAKE_MODULE_H is not already defined, process the following code.
#define FAKE_MODULE_H Defines the symbol so a later inclusion can be recognized.
#endif Ends the conditional preprocessor block.

First Inclusion

  1. FAKE_MODULE_H is not defined.
  2. #ifndef is therefore true.
  3. The header contents are processed.
  4. #define FAKE_MODULE_H marks the header as already included.

Later Inclusion

  1. FAKE_MODULE_H is already defined.
  2. #ifndef is false.
  3. The preprocessor skips the contents until #endif.
Why the #define matters: #ifndef only checks whether a symbol exists. It does not create the symbol. Without the #define, the test would remain true every time.

6. Compiling and Linking Multiple Files

Building a C program usually involves several stages. Two especially important stages are compilation and linking.

Compilation

Each .c file is translated into machine-code-like object code. The result is usually an .o file on macOS/Linux or an .obj file on Windows.

Linking

The linker combines object files and libraries, then connects function calls to their actual definitions.

Compile Without Linking

gcc -c fake_module.c -o fake_module.o
gcc -c main.c -o main.o

This creates:

  • fake_module.o — compiled code for the module.
  • main.o — compiled code for the application.

Link the Object Files

gcc main.o fake_module.o -o main

Compile and Link in One Command

gcc main.c fake_module.c -o main
Source files (.c) | | compilation v Object files (.o) | | linking v Executable

A Useful Missing Detail: Preprocessing Happens First

Before normal compilation, the C preprocessor handles directives such as #include, #define, and conditional compilation directives.

Preprocessing ---> Compilation ---> Assembly/Object Code ---> Linking

A header file is normally not compiled by itself. Its text is effectively inserted where the corresponding #include directive appears.

7. Information Hiding

Information hiding means keeping implementation details private and exposing only what other parts of the program actually need.

  • Abstraction: focuses on what a module does.
  • Information hiding: prevents outside code from depending on how it is implemented.

Example

The header exposes the public operations:

int getx(void);
void setx(int value);

The source file contains a private variable:

static int x = 0;

Because x is not part of the public header, code using the module should interact with it through getx() and setx(). 

#include "fake_module.h"

int main(void) {
    setx(42);
    return getx();
}

Invalid Direct Access

#include "fake_module.h"

int main(void) {
    x = 42;    // Error: x is not visible here.
    return x;  // Error
}

Benefits of Information Hiding

  • Protects internal state from accidental changes.
  • Reduces how many details the programmer needs to understand at once.
  • Makes modules easier to test.
  • Makes future implementation changes safer.
  • Reduces unintended dependencies between files.

8. Important Gap: What static Means Here

In the example below, static is being used at file scope: 

static int x = 0;

At file scope, static gives the variable internal linkage. In practical beginner terms, the name x is usable only inside that source file.

The same idea can be used for private helper functions:

static int clampValue(int value) {
    if (value < 0) return 0;
    if (value > 100) return 100;
    return value;
}

Other source files cannot directly call clampValue() by name. This is useful when the function is only an internal implementation detail.

Do not confuse this with a local static variable. A static variable declared inside a function has a different purpose: it keeps its value between function calls.

9. Important Gap: Translation Units

A translation unit is, roughly, one source file after the preprocessor has inserted its included headers and handled preprocessor directives.

For example:

// main.c
#include <stdio.h>
#include "fake_module.h"

During preprocessing, the declarations from the included headers become part of the translation unit that is compiled for main.c.

This explains why an include guard only needs to prevent duplicate processing inside one translation unit. The same header can and normally should be included separately by many different .c files.

10. Important Gap: Good Header File Rules

Rule 1: Put Declarations in Headers

// good
int getx(void);
void setx(int value);

Rule 2: Put Ordinary Function Definitions in Source Files

// fake_module.c
int getx(void) {
    return x;
}

If a normal non-static function definition is placed in a header and that header is included by several source files, the linker may report multiple definitions.

Rule 3: Include Your Own Header in the Implementation

#include "fake_module.h"

This lets the compiler check that your function definitions agree with the declarations in the header. It would help catch a mistake such as declaring setx(int) but defining setx(int *).

Rule 4: Include Only What the Header Needs

A header should be as self-contained as practical. If a public declaration needs a type from another header, include that dependency or use an appropriate forward declaration.

Rule 5: Avoid Public Global Variables When Possible

Public global variables increase coupling between modules. Getter/setter functions or other operations often provide better control over how data is accessed.

11. Common Errors and What They Mean

Problem Typical meaning Possible fix
implicit declaration of function The compiler saw a function call before seeing its declaration. Include the correct header or add the proper prototype.
conflicting types for ... A declaration and definition disagree. Make the return type and parameter types match exactly.
undefined reference / undefined symbol The compiler accepted the declaration, but the linker cannot find the function definition. Compile and link the source file containing the definition.
multiple definition of ... The linker found the same externally visible definition more than once. Move ordinary definitions out of headers or check for duplicate global definitions.
undeclared identifier The current source file cannot see that name. Check scope, headers, spelling, and whether the item was intentionally made private.

Declaration vs. Definition

This is a declaration:

int getx(void);

This is a definition:

int getx(void) {
    return x;
}
A declaration tells the compiler that something exists and describes its type. A definition actually creates the function or object.
